# 分配批次复盘页设计

## 背景

系统已经具备学生管理、线索治理、智能分配、操作日志和分配批次回滚能力。智能分配解决了“怎么把未分配线索公平地分给坐席”的问题，但执行后还缺少一个清晰答案：这批线索分下去以后有没有被及时处理、哪些坐席处理得慢、哪些学生仍然没有推进。

下一步优先补齐“分配效果复盘”。第一版聚焦分配批次本身，不先做更复杂的坐席长期排行或学校/地区转化分析。批次复盘会成为后续优化智能分配策略、自动运营提醒和坐席管理的基础数据层。

## 目标

- 为每个分配批次提供独立复盘页，支持从审计日志进入，也支持智能分配执行成功后进入。
- 展示批次概览、处理漏斗、坐席拆分和未处理名单。
- 支持切换统计窗口：1 天、3 天、7 天、14 天。
- 统计窗口从批次分配时间开始，到批次分配时间加所选天数结束。
- “有效处理”第一版只按状态推进判断：学生在统计窗口内进入非未联系类状态即算有效处理。
- 保持只读复盘，不改变现有学生分配、智能分配、审计和回滚流程。

## 非目标

- 不在第一版做自动二次分配。
- 不在第一版做坐席长期 KPI 排行页。
- 不在第一版做学校/地区转化漏斗。
- 不引入转化率模型或智能评分。
- 不新建分配批次表；批次识别继续基于 `OperationLog.batch_id`。
- 不重写现有审计日志和回滚逻辑。

## 决策

### 入口

第一版入口放在两个地方：

- 审计日志中有分配批次号和可回滚入口的位置，增加“复盘”入口。
- 智能分配执行成功结果中增加“查看复盘”入口。

暂不在线索治理页新增单独菜单卡片，避免入口过多。复盘对象是“批次”，从操作记录和执行结果进入最自然。

### 权限

页面访问使用 `audit_logs` 页面权限。超级管理员自动允许。

原因：

- 复盘依赖操作日志批次号，本质属于审计/运营追踪。
- 审计日志页面已经是历史批次的主要入口。
- 第一版保持权限边界简单，不额外增加权限项。

本次不放宽给 `lead_governance`；线索治理入口可以通过审计日志间接进入，但页面本身只校验 `audit_logs`。

### 统计窗口

支持四个固定窗口：1、3、7、14 天。默认 7 天。

后端参数：

```text
GET /api/admin/assignment-batches/{batch_id}/review?window_days=7
```

合法值只允许 `1 | 3 | 7 | 14`。非法值返回 422 或统一错误响应，前端只提供固定选项。

### 有效处理口径

第一版只看状态推进：

- 窗口内存在状态变更日志，且 `new_status` 可归一到非未联系类状态，则计为有效处理。
- 如果没有状态变更日志，但学生当前状态已是非未联系类，且 `Student.updated_at` 落在窗口内，也计为有效处理。
- 非未联系类状态包括：已联系、未接、待回访、已报名、无效，以及这些状态的历史兼容别名。

不把写备注、创建回访任务或通话记录直接计入有效处理。这样口径更稳定，也避免低质量备注把处理率冲高。

### 数据来源

- 分配批次学生：从 `OperationLog` 中按 `batch_id` 查找分配动作日志，动作包含现有可回滚分配动作和 `智能分配`。
- 批次概览：优先使用汇总日志，例如 `智能分配汇总`、`学校分配汇总`、`自动分配汇总`。没有汇总日志时，用最早一条分配日志兜底。
- 坐席归属：从分配日志的 `note_content` 解析 `new_assigned_to`；解析失败时使用学生当前 `assigned_to` 兜底，但该项在复盘中标记为不可完全回溯。
- 拨打：`DialLog.student_id` 在窗口内存在记录即算已拨打。
- 有效处理：窗口内存在状态变更日志使学生进入非未联系类状态，或学生当前状态已是非未联系类且 `Student.updated_at` 在窗口内。
- 报名：学生当前状态归一为 `StudentStatus.enrolled`，或窗口内存在该学生的报名记录，任一满足即算报名。

### 风险提示

第一版提供轻量规则：

- 未拨打率超过 30%：高风险。
- 有效处理率低于 50% 且分配人数不少于 10：中风险。
- 任一坐席未拨打率超过 50% 且分配人数不少于 5：中风险。

这些提示只展示，不自动写操作日志，不触发任务。

## 前端设计

新增页面：

```text
frontend/src/pages/admin/AssignmentBatchReview.jsx
```

路由：

```text
/admin/assignment-batches/:batchId/review
```

页面结构：

- 顶部：批次号、分配时间、窗口切换、返回审计日志。
- 指标区：已分配、已拨打、有效处理、已报名。
- 漏斗区：展示已分配 → 已拨打 → 有效处理 → 已报名。
- 坐席表：按坐席展示分配数、拨打数、有效处理数、报名数和对应比例。
- 未处理名单：展示窗口内未拨打或未有效处理的学生，链接到学生详情。
- 风险提示：展示后端返回的 alerts。

智能分配执行成功后，在成功提示区域增加链接：

```text
查看复盘
```

链接指向：

```text
/admin/assignment-batches/{batch_id}/review
```

审计日志中，当日志具备 `batch_id` 且 `can_rollback_assignment` 为真，或动作属于分配汇总动作时，展示“复盘”链接。回滚入口保持原样。

## 错误和空状态

- 批次不存在：显示“未找到该分配批次”。
- 批次存在但没有可统计学生：显示“该批次暂无可复盘线索”。
- 窗口内没有拨打/处理：指标显示 0，未处理名单展示全部学生。
- 部分日志缺少回滚元数据：尽量展示统计，并在页面提示“部分学生缺少完整分配回溯信息”。

## 测试计划

### 后端

- 批次复盘接口要求 `audit_logs` 页面权限。
- 支持窗口参数 1、3、7、14，非法窗口返回错误。
- 正确统计批次分配人数、拨打数、有效处理数、报名数。
- 正确按坐席拆分统计。
- 能列出未拨打和未有效处理学生。
- 对不存在 batch 返回清晰错误。
- 对缺少汇总日志的批次能用分配日志兜底。

### 前端

- 路由权限测试：`/admin/assignment-batches/:batchId/review` 需要 `audit_logs`。
- 页面加载后展示批次概览、漏斗、坐席表、未处理名单。
- 切换 1/3/7/14 天窗口会重新请求接口。
- 空状态和错误状态可见。
- 智能分配成功后显示“查看复盘”链接。
- 审计日志中的批次展示“复盘”链接。

### Playwright

- Mock API 后从审计日志进入复盘页，验证页面标题、窗口切换和核心指标可见。

## 实施顺序

1. 后端统计服务和接口。
2. 后端接口测试。
3. 前端复盘页和路由。
4. 智能分配成功入口和审计日志入口。
5. 前端测试和 Playwright smoke。

## 验收标准

- 管理员能从智能分配成功结果进入该批次复盘页。
- 管理员能从审计日志中的分配批次进入复盘页。
- 复盘页支持 1、3、7、14 天窗口切换。
- 页面展示批次概览、漏斗、坐席拆分、未处理名单和风险提示。
- 后端、前端单测、ruff、build、Playwright smoke 全部通过。
