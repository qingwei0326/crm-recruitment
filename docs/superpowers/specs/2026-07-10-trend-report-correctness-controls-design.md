# 趋势报表统计正确性与交互完善设计

## 背景

趋势报表已经取消固定前 5 名展示上限，但当前实现仍存在五类问题：

- 后端和前端使用话务员姓名作为数据键；姓名不是数据库唯一字段，存在覆盖风险。
- 拨号时间以 UTC 无时区时间存储，趋势接口却直接按数据库日期分组，没有使用系统其他报表已经采用的北京时间边界。
- “本周”和“本月”实际是滚动 8 天和 31 天，与按钮文字不一致；本周范围内的上周同期也只有一个有效点。
- CSV 仅导出日期、总呼出量和报名数，没有导出页面展示的话务员明细。
- 人员继续增加后，默认展示全部曲线会降低可读性，但不能重新引入固定人数上限。

## 目标

- 使用话务员 ID 作为趋势数据的唯一标识，姓名只作为展示文本。
- 已离职话务员在所选范围内有历史呼出时继续显示；范围内无呼出时隐藏。
- 总呼出量只统计话务员账号，并与各话务员呼出量之和一致。
- 所有日期筛选和每日分组统一使用北京时间。
- “本周”表示本周一至今天，“本月”表示当月 1 日至今天。
- 每个当前日期都返回七天前的同期呼出量。
- 自定义日期得到前后端双重校验，查询范围最多 366 个自然日。
- CSV 包含所有有呼出话务员的每日数据。
- 默认展示全部曲线，并允许管理员通过图例临时隐藏或恢复单条曲线。
- 支持前后端分步部署，不让仍在运行的旧页面立即失效。

## 非目标

- 不修改拨号记录、学生报名记录或账号数据。
- 不修改通电量查询、话务员排行或招生经营报表的统计口径。
- 不在数据库层给姓名增加唯一约束；业务上继续要求话务员姓名不重复。
- 不增加报表分页、前 N 名模式或持久化个人图表偏好。
- 不在本次改动中部署生产环境。

## 接口契约

GET /api/stats/trend 保持原路径，响应扩展为：

    {
      "agents": [
        {
          "id": 14,
          "name": "邹欣辰",
          "is_active": true
        }
      ],
      "daily": [
        {
          "date": "2026-07-10",
          "calls": 354,
          "enrolled": 0,
          "prev_calls": 120,
          "agent_calls_by_id": {
            "14": 354
          },
          "agent_calls": {
            "邹欣辰": 354
          }
        }
      ],
      "start": "2026-07-01",
      "end": "2026-07-10"
    }

新前端只把 agents 和 agent_calls_by_id 作为主契约。agent_calls 保留一个兼容周期，供部署过程中仍在运行的旧前端读取；旧字段按姓名累加，避免异常同名数据直接覆盖。

新前端也保留旧响应兼容：当 agents 或 agent_calls_by_id 缺失时，从旧的 agent_calls 构造临时系列。因此前端先部署或后端先部署都能继续显示报表。

## 后端设计

### 人员与呼出量

话务员元数据查询包含所有 role=agent 账号，不按 is_active 过滤，并按 ID 排序。这样离职人员的历史数据仍可归属到原账号。

呼出量查询只统计这些话务员 ID，不把管理员取号或异常孤立记录计入趋势总量。一个聚合查询覆盖“当前范围开始前 7 天”至当前范围结束，按北京时间日期和话务员 ID 分组。

对每个当前日期：

- agent_calls_by_id 返回每名话务员的呼出量，缺少记录时为 0。
- calls 等于当日 agent_calls_by_id 的数值总和。
- prev_calls 等于该日期前 7 天所有话务员呼出量的总和。
- 兼容字段 agent_calls 按姓名累加相同 ID 结果。

### 北京时间

日期参数使用 FastAPI 的 date | None 类型，让非法格式自动返回 422。

新增共享时间函数：

- today_cst_date() -> date：返回北京时间今天。
- cst_date_start_as_utc(day: date) -> datetime：把北京时间某日 00:00 转成数据库使用的无时区 UTC 时间。

查询边界统一使用该转换。每日分组表达式按数据库引擎选择：

- SQLite：date(dialed_at, '+8 hours')。
- PostgreSQL：UTC 无时区时间加 8 小时后转为 date。

该分支集中在趋势统计模块的一个小函数中，避免业务查询散落数据库方言判断。

### 默认范围与校验

未传日期时：

- end 为北京时间今天。
- start 为 end 所在月份的 1 日。

只传开始日期时，结束日期取北京时间今天；只传结束日期时，开始日期取该结束日期所在月份的 1 日。最终统一校验：

- start <= end。
- 按 (end - start).days + 1 计算，包含首尾日期后的总天数不超过 366。

违反规则返回 HTTP 422 和可直接展示的中文错误信息，不进入数据库查询。

## 前端设计

### 数据适配

新增趋势报表领域工具模块，负责：

- 把新旧接口响应规范化为统一的话务员列表与 ID/临时键呼出量映射。
- 计算所选范围内累计呼出大于 0 的话务员。
- 为每个系列生成不含姓名路径字符的安全 seriesKey。
- 生成北京时间的自然周、自然月查询范围。
- 生成并转义 CSV。

图表、明细表和导出都消费同一份规范化数据，避免三处分别解释接口字段。

### 自然周与自然月

“本周”发送北京时间本周一至今天；“本月”发送北京时间当月 1 日至今天。首次加载可以不传参数，由后端返回自然月默认范围。

前端不使用 toISOString() 推导北京时间日期，避免北京时间凌晨得到前一天。自定义查询在请求前检查开始日期、结束日期、先后顺序和 366 天上限；失败时显示提示并保留当前报表。

周同比直接读取后端 prev_calls，不再从当前返回范围内反查七天前数据。

### 图例开关

话务员曲线默认全部显示。图例使用带颜色标记的可交互复选项：

- 取消勾选只隐藏对应曲线。
- 图例项本身保持可见，允许重新勾选。
- 存在隐藏项时显示“全部显示”命令。
- 日期范围或接口数据变化后重置为全部显示。

图例开关只影响图表，不影响数据明细和导出，避免临时视觉操作改变报表数据含义。

### CSV 导出

CSV 表头为：

    日期,呼出量,报名数,<所有范围内有呼出的话务员姓名...>

每行追加对应话务员的当日呼出量。导出包含全部有呼出人员，不受图例隐藏状态影响。所有字段统一执行 CSV 转义，正确处理逗号、双引号和换行。

## 错误处理

- 新响应字段缺失时自动使用旧字段，不因部署顺序显示空白页。
- 非法日期由前端阻止；直接调用接口时由后端返回 422。
- 接口返回可展示的错误消息时，前端优先显示该消息；未知错误继续显示“数据加载失败”。
- 空数据仍显示现有空态，不创建无意义的零值曲线。
- 单个话务员被图例隐藏不会改变其他系列颜色。

## 测试计划

### 后端

- 两个不同 ID 使用相同姓名时，agent_calls_by_id 分别保留数据，兼容姓名字段正确求和。
- 已离职话务员有呼出时返回历史数据，无呼出时仍有元数据但数值为 0。
- 管理员拨号不进入话务员趋势总量，calls 等于 ID 明细之和。
- 北京时间 00:00 前后对应的 UTC 时间进入正确自然日。
- SQLite 日期分组表达式正确；PostgreSQL 表达式可成功编译。
- 默认范围为北京时间当月 1 日至今天。
- 开始晚于结束、非法日期和超过 366 天均返回 422。
- 每个日期都返回正确的 prev_calls。

### 前端

- 新 ID 契约显示全部正呼出人员并隐藏零呼出人员。
- 旧姓名契约仍能正常显示。
- 本周生成周一至今天，本月生成 1 日至今天，且北京时间凌晨不偏移。
- 无效自定义日期不发送请求并显示明确提示。
- 图例复选项可以隐藏、恢复单条曲线，“全部显示”恢复所有曲线。
- 图例隐藏不影响表格列和 CSV。
- CSV 包含话务员列并正确转义特殊字符。
- 现有超过 5 人、全部为 0 和主趋势系列测试继续通过。

### 验收

1. 后端趋势报表定向测试先失败后通过。
2. 前端趋势报表定向测试先失败后通过。
3. 全量后端测试、Ruff、前端测试、ESLint 和生产构建通过。
4. 本地桌面与移动宽度检查全部曲线、图例开关、横向表格和导出。
5. Git 差异不包含生产数据库、配置文件或用户已有的删除项。

## 验收标准

- 页面和导出均以话务员 ID 归属呼出量。
- 所有统计日期与筛选范围使用北京时间。
- 自然周、自然月和上周同期含义与页面文字一致。
- 离职人员有历史数据时显示，无数据时隐藏。
- 总呼出量与话务员明细之和一致。
- 默认显示全部曲线，管理员可临时切换任意曲线。
- 新旧前后端任意部署顺序都能继续展示趋势报表。
